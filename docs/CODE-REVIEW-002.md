# Повторная ревизия и измеренная оптимизация

SYS-223, 2026-11-12. Исходный снимок `222c6d7`. Codex проверил runtime controller/worker, преобразователь, provider/router, theme watcher, границы native fixture и runner. Это целевая повторная ревизия с тестами, не полный формальный аудит каждой строки, ОС или всех транзитивных зависимостей. Работа выполнена в отдельном worktree; исходная ветка не изменялась.

## Проверка через Context7

Удалённый Context7 MCP реально использован: resolve-library-id и три query-docs по Qt. Выбран `/websites/doc_qt_io_qt-6`, официальный источник; отдельный индекс именно 6.12 не был предоставлен. Запрашивались только публичные понятия/API, без исходников, путей, слов, ключей и сведений о пользователе. Ответы — ориентир для ревизии, не доказательство поведения конкретного бинарника Qt 6.12.0.

- [QThread](https://doc.qt.io/qt-6/qthread.html) и [QObject](https://doc.qt.io/qt-6/qobject.html): worker-object, принадлежность потоку, завершение, deleteLater. Наш provider создаётся/вызывается/уничтожается одним worker, finished связан с deleteLater, поток join'ится перед удалением. Найденного основания менять эту схему нет.
- [QProcess](https://doc.qt.io/qt-6/qprocess.html): waitFor* блокируют вызывающий поток и могут заморозить GUI. В native fixture такое ожидание специально создаёт контролируемый порядок; копировать его в production event loop нельзя. Нужен асинхронный автомат по signals/deadline, если выбранный backend вообще предоставит требуемое подтверждение.
- [QFileSystemWatcher](https://doc.qt.io/qt-6/qfilesystemwatcher.html): при атомарной замене файла наблюдение может пропасть; его нужно восстанавливать. Поэтому rearm удалять нельзя. Возможное улучшение — добавлять/удалять только изменившиеся watches; выгода ещё не измерена, изменение не внесено.

## Что уже устроено разумно

- AnalysisService ограничивает работу одним выполняющимся и одним новейшим ожидающим запросом. MemoSource разделяет одно evidence lookup между safe/requested профилями. Не добавляем pool, постоянный polling или неограниченную очередь.
- DocumentController проверяет revision/field epoch/layout/profile generation перед применением; редактирование отменяет derived state. Проверки актуальности не удалялись ради скорости.
- Layout/router отказываются от unknown/protected/unsupported контекста до evidence. В новом fixture начальный synthetic keyboard ввод также требует normal hints и пустого поля.
- В просмотренном runtime src не найдено вызовов QProcess, QSettings, QNetwork/QTcp/QUdp, system/popen или текстового debug logging. Это поиск конкретных API, не доказательство отсутствия всех возможных эффектов Qt/plugins.
- Проверки SHA-256, notices, passport и direct-caller bounds у provider не удалялись: повторение на границе API здесь намеренное.

## Реализованное улучшение преобразователя

Раньше lookup для каждой кодовой единицы перебирал до 94 пар. Теперь прямой индекс вычисляется constexpr **из той же единственной таблицы**: US ASCII, reverse ASCII, reverse Cyrillic U+0400..U+045F и отдельный знак номера. Неизвестный символ остаётся неизменённым; суррогаты и combining clusters сохраняют прежнее поведение. Нет hash map, runtime-инициализации таблицы, новых heap allocations или изменяемого глобального состояния.

`static_assert(indexCoversTable())` проверяет покрытие каждой пары в обоих направлениях. Если будущая раскладка выходит за индексируемые диапазоны, сборка откажет, а символ не потеряется молча. Исходные compile-time проверки уникальности и отсутствия surrogate/space сохранены.

Добавлен тест по независимым строкам клавиатуры, уже существовавшим в tests: все 65 536 UTF-16 значений, два направления, одиночный символ и символ с combining mark — 262 144 сравнений. Он не использует production mapping как oracle. Дополнительный developer probe сравнил старую и новую реализации в 393 216 случаях, включая supplementary combining mark.

### Измерения

GCC 16.2.1, Qt 6.12.0, C++17, `-O2`, без LTO. Один фиксированный синтетический 32-unit шаблон и его повтор до 65 536 units. Пять samples, порядок baseline/candidate чередуется; median. Внутри sample 100 000 short либо 100 long вызовов; checksum предотвращает удаление вычислений. Nice +10, 20 s CPU cap/1 GiB AS cap; без GUI, сети, словарей/модели и физических устройств. CPU не закреплялся, повторные прогоны не являются независимой статистической выборкой.

| Вход | До, median на вызов | После | Отношение |
| --- | --- | --- | --- |
| 32 UTF-16 units | 1,654 мкс | 0,241 мкс | 6,86× |
| 65 536 UTF-16 units | 3,351 мс | 0,452 мс | 7,42× |

Это ускорение чистой функции на двух шаблонах, не всей программы, IME или детектора. Не измерены все классы текста, p95, задержка реального набора и power consumption. Для короткого слова абсолютная экономия мала по сравнению с миллисекундными IPC/GUI задержками; оптимизация не решает проблему безопасной замены текста.

У сопоставимых layoutconverter.o `.rodata` 376 → 570 байт (+194), `.text` 673 → 679; `.eh_frame` 160 → 152; суммарный section total 1450 → 1642 (+192). Это объектный файл, не размер дистрибутива или прирост RSS; выравнивание и линковщик могут изменить итог.

Developer probe и сырой JSON остаются в build; публичны агрегаты/fingerprints. После замечаний ревью выполнен повторный замер финальной версии; таблица выше обновлена. Точная воспроизводимость timing из чистого клона пока не обеспечена отдельной benchmark-целью.

## Проверки

- Исходная ветка: 602 Qt passed, 0 failed, 1 optional real-profile skip.
- Кандидат: 603 Qt passed, 0 failed, 1 тот же skip. Сборка с нуля в отдельном worktree; GUI tests только offscreen/software.
- ASan + UBSan + LeakSanitizer: 14 целевых cases passed, диагностик нет. Первый запуск в инструментальном sandbox завершил проверки, но LSan не смог выполнить внутреннюю ptrace-проверку; повтор с разрешённым доступом для sanitizer завершился 0. Проверки утечек не отключались.
- Mocked nested runner: 22 passed; compositor и устройства при этом не запускались.
- Реальные model/dictionary artifacts в этой ревизии не читались. Установки, изменения системной конфигурации и запуск background backend отсутствуют.

## Оставшиеся задачи по приоритету

1. **Блокер автоисправления:** гарантировать применение к нужному полю/версии на принимающей стороне либо доказать иной вводный pipeline. Test ACK/one-key gate не предоставляют capability сторонних редакторов; Space остаётся trigger, а не транзакцией. См. INPUT-LAB-003/004.
2. **Для будущего backend:** явные состояния queued/validated/sent/applied/uncertain и асинхронные timeouts. После начала записи нельзя считать abort безопасным rollback; запрещён blind retry при неопределённом исходе. Это контракт для будущей реализации, не текущий готовый компонент.
3. **Shutdown/resource:** AnalysisService ждёт выполняющуюся загрузку/проверку без жёсткого deadline. Для нынешнего доверенного pinned provider это известное ограничение, не доказанный hang. Если потребуется жёсткое время завершения, изоляция в отдельном процессе требует отдельного дизайна; QThread::terminate не предлагается.
4. **Большая вставка:** предел 65 536 ограничивает принятый документ, но Qt может выделить память до отклонения огромной вставки. Не заявляем ограничение пикового RSS; нужен отдельный sandbox stress-test синтетической вставки.
5. **Watchers:** измерить частоту wakeups на parent directory и проверить delta-rearm при atomic replacement/missing path/symlink theme switch. Не удалять parent watches и debounce без проверки поведения.
6. **Воспроизводимость/выпуск:** private GPL compositor не распространяется, поэтому серверный опыт не воспроизводится чистым клоном. Лицензию своего релиза и допуск данных ещё нужно решить отдельно; этот PR их не выбирает.

Оптимизация написана на основе собственного существующего кода и таблицы. Код/данные аналогов и примеры Context7 не копировались; зависимостей не добавлено. Автор не объявляет собственную правку независимо одобренной; результат отдельного Claude review указан ниже.

## Доработка по независимому ревью

Claude проверил три публичных source/test файла без инструментов, MCP, hooks/plugins и сохранения сессии. В первоначальном ревью блокирующих замечаний не найдено; он явно не воспроизводил наши тесты и замеры. Неблокирующие замечания устранены: диапазоны именованы, lookup стал constexpr, а compile-time coverage вызывает сам lookup в обоих направлениях. Это проверяет фактический путь поиска, а не отдельную копию его логики.

В 23 Unicode fixture literals невидимые/combining символы заменены явными escape-последовательностями. Скрипт проверил совпадение декодированных значений до/после; исходные примеры уже были корректно разложены. Для исчерпывающего теста добавлен контекст ошибки U+XXXX, направление и вариант. Новые комментарии приведены к языку файла. O(1) относится к lookup одной кодовой единицы, не к защите от side channels; convertLayout по-прежнему может выделять память при detach QString.

После правок полная серия снова 603/0/1, targeted ASan/UBSan/LSan снова 14/0, developer equivalence снова 393216 совпадений. Безопасность системного backend из этих результатов не следует.

Повторное независимое Claude review финальной версии завершено: блокирующих замечаний нет в трёх переданных файлах. Остаются неблокирующие возможности усиления compile-time проверки количества непустых слотов и дополнительный пример spacing combining mark; отсутствие лишних ячеек уже закрывает полный runtime oracle. Ревьюер не запускал тесты и не подтверждал наши численные замеры. Автоматическое исправление других приложений этим ревью не допущено.
