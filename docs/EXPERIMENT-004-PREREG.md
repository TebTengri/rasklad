# Предрегистрация опыта 004: технический текст

SYS-236, 2026-11-11. Полный [протокол](../data/experiment-004-protocol.json) фиксируется до получения chapter-текстов и расчёта исходов. Модель, словари и пороги опыта 003 неизменны. Новый домен — 20 hash-selected Markdown глав EN Rust Book и 20 глав русского перевода, версии зафиксированы в JSON. Полные MIT/Apache/COPYRIGHT notices и [review](../data/notices/TECHNICAL-004-REVIEW.md) получены отдельно до корпуса.

Основной вопрос: сохраняется ли польза компактной модели как подтверждения на технической прозе, и какую цену имеет fallback. Отдельный контроль — oracle запрет любых изменений размеченного inline/fenced code. Markdown известен оценщику; это не реализация распознавания безопасного поля на рабочем столе.

Все исходные prose/code tokens имеют intent Keep; их изменения ложны даже при словарной неоднозначности. Wrong-копии создаются только из native-letter-only prose; общий union stem/control/full ambiguity запрещает считать неоднозначные изменения восстановлением. Typed layout задаётся по script oracle: RU letters → ru, иначе us; английские термины в русском тексте не объявляются ошибками раскладки. Смешанные/неподдерживаемые строки не отфильтровываются. Регистр сохраняется. Подробные Markdown/token правила зафиксированы в JSON до текста; это ограниченный parser, не визуальная семантика CommonMark.

Девять вариантов: alwaysKeep; model/full/confirmed/fallback; четыре соответствующих варианта с oracle code protection. Порогов/исключений по новому test не выбираем. Таблица содержит все варианты, обе роли, occurrences и exact-case types, языки, документы и ambiguity. Из-за повторов слов нет IID confidence claims. Переводы двух языков тематически коррелируют; это один новый технический домен.

Исследовательский screen: не более одной ложной замены на 10 000 eligible prose valid вхождений И exact-case типов для каждого языка и pooled; ноль изменений protected code; восстановление не менее 50% eligible unambiguous wrong для каждого языка и pooled. Нулевой знаменатель → insufficient. Это инженерный фильтр, не доказательство production-частоты. Деноминатор eligible: supported и >=4 keys, чтобы неподдерживаемый код/короткие слова не разбавляли частоту ошибок. AlwaysKeep должен провалить recovery-часть.

D1: confirmation уменьшает unsafe против full ценой recoveries; равенство → inconclusive. D2: fallback даёт paired recoveries сверх full с обязательным учётом added false/ambiguous/code changes. D3: protection предотвращает >0 protected changes без изменения prose; если raw changes отсутствуют, выигрыш не доказан. D4: screen всех вариантов pass/fail/insufficient без подбора победного порога. Нового жанра недостаточно для допуска автоматического ввода; этот test после опыта становится диагностическим.
