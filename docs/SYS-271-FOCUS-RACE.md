# SYS-271: исправление и смена фокуса

Вопрос из ревизии перед выпуском: может ли исправление или отмена уйти в другое
поле, если фокус сменился раньше, чем это увидел Fcitx.

## Стенд

Продуктовый набор `focus` в `tools/wayland_ime_lab.py`: headless Sway, Chromium
на Wayland с text-input-v3, настоящий Fcitx с пакетным аддоном. Страница с двумя
полями. В первом набирается `ghbdtn`, затем отправляется пробел (исправление)
или двойной Shift после пробела (отмена), и через 0–50 мс скрипт страницы
переводит фокус во второе поле.

```sh
python3 tools/wayland_ime_lab.py --run --product-suite focus --packaged --input-root "$profile"
```

## Результат (0.5.22)

| Задержка | Исправление | Отмена |
| --- | --- | --- |
| 0 мс, 5 раз | 5 из 5: `привет ` во втором поле, `ghbdtn` в первом | ни разу не ушла |
| 1 мс, 3 раза | ни разу | ни разу |
| 2–50 мс | ни разу | ни разу |

При 0 мс фокус меняется раньше, чем клавиша доходит до Fcitx. Аддон получает
пробел, пока поле для него ещё прежнее, и отправляет исправление. Chromium
применяет пришедший текст к полю, которое в фокусе сейчас, а о смене поля
сообщает системе позже. Fcitx в этот момент смены не видит. Обычная клавиша без
Rasklad в том же случае тоже уходит в новое поле; с Rasklad туда уходит
исправленное слово.

Отмена удаляет и вставляет текст одной фиксацией протокола input-method-v2, то
есть атомарно. Двойной Shift после смены фокуса не срабатывает.

## Вывод

- Окно меньше 1 мс и возникает, только когда скрипт страницы двигает фокус в тот
  же миг, что и нажатие. Смена фокуса пользователем (щелчок, Alt+Tab) приходит
  через композитор по порядку с клавишами.
- На стороне аддона этот случай не закрыть: в протоколе нет адреса поля, а
  проверки перед отправкой (`hasFocus`, окружающий текст) в этот момент ещё
  видят старое поле.
- Набор `focus` требует, чтобы при задержке от 2 мс во второе поле ничего не
  попадало, а первое поле оставалось в одной из ожидаемых форм. Утечки при 0–1 мс
  он записывает в `focusLeaks`, не требуя их отсутствия.
- Стенд — Sway, не Hyprland. Проверка во вложенном Hyprland
  (`tools/hyprland_ime_lab.py`) требует отдельного разрешения владельца.
