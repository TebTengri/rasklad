# SYS-242 — числовой scorer и интерфейс словарной evidence

2026-11-13. Продолжение browser core 002.

## Сохраняем выбранную схему

Для автоматического исправления SafeConfirmed требует согласия полноценной
словарной проверки и маленькой n-gram модели. Известный исходный вариант
сохраняется, shared ambiguity отменяет замену. RequestedHybrid может предложить
вариант, но Suggest не превращается в автоматическую правку.

Browser core 002 уже использует экспортированную таблицу настоящего C++ router.
Текущий шаг переносит только небольшой числовой scorer и привязывает его к
явному синхронному интерфейсу словарей. Это не новая схема распознавания.
Поскольку установленного WASM SDK нет, арифметика имеет браузерную реализацию,
которую проверяем по нативному эталону. Не называем её выполнением всего C++
ядра в браузере или одним общим бинарником.

## Формат и данные

Параметры формата и frozen thresholds экспортируются из существующих C++
констант: RSKN v1, 20-байтовый заголовок и 88 270 знаковых int8 весов (EN/RU).
Всего 88 290 байт. Проверки формата не заменяют SHA-256, provenance, license
admission или подпись выпуска. Подлинный разрешённый browser data package пока
не подготовлен; существующие реальные артефакты в этой работе не открывались.

Developer fixture создаёт семь полностью искусственных числовых таблиц:
псевдослучайную детерминированную, плоские контрасты EN/RU, равные/нулевые/
предельные веса и отдельную таблицу для сквозных вымышленных сценариев. Это не
обучение на корпусе и не языковая точность. Оригинальные искусственные данные
генерируются в ignored build/, в Git не входят. Для fixture единственная модель
встраивается в synthetic-model.js как base64; этот developer способ доставки
не является оценкой размера будущего release package.

## Проверка переноса

Независимый C++ generator получает оценки и действия непосредственно от
NgramModel::deserialize/score и decideTwoScore. Клавиши длиной 1–32, BOS/EOS,
пять числовых шаблонов, недопустимые последовательности и границы threshold
проверяются без словаря, корпуса или естественного ввода. Browser test сравнивает
целые raw scores и решения US/RU, а не только несколько удачных слов.

Реализация: Claude Opus 5.5 подготовил browser/scorer.js. Первый большой запрос
завершился тайм-аутом без результата; после разделения задания scorer получен.
Codex независимо написал native conformance generator, evidence binding и тесты,
проверил scorer и усилил отказ на spoofed SharedArrayBuffer/исключительных getters
с общей ошибкой без содержимого входа. Никаких runtime облачных вызовов нет.

Результаты: 1 176 scores и 2 464 US/RU model decisions совпали с C++ как в Node,
так и в изолированном Chromium 155. В том числе недопустимые keys и threshold
boundaries. Node: 10 security/evidence cases + 1 conformance test с этими сравнениями,
а также прежние 12 router tests (все 512 состояний) и 13 adapter/converter tests.
Browser: 31 assertion, включая полный native conformance.
После подключения scorer измерение 50 Space baseline и 50 с коррекцией дало
p95/max около 0,1 мс при дискретности ~0,1 мс; это не физическая/render latency и
не замер настоящих словарей. JS heap всей fixture до тяжёлого conformance ~1,42 MB,
не RSS и не изолированная добавочная память. Сам сериализованный RSKN — 88 290 B;
fixture base64 wrapper ~118 KB не равен будущему бинарному packaging. Повреждённые заголовки,
веса -128/positive, неверные размеры/score shape, subarray snapshot, disposal,
Promise/nonboolean dictionary ответы и прямые malformed query проверены.

Сквозной путь fixture больше не присваивает model action по слову: он читает
искусственные байты, вычисляет n-gram scores и frozen twoScore; full/control/stem
membership остаётся явно искусственным. Две независимые проверки нужны до
автозамены, как в принятой архитектуре. Это проверка реализации, не точности языка.

## Словарная часть

Три явных интерфейса — full(language, exactToken), control(language, exactToken)
и stem(language, canonicalKeys). Они должны обеспечивать те же признаки, что
нативный LocalEvidenceProvider. Missing/throwing/asynchronous/небулевый ответ
означает отсутствие пригодной evidence; подстановка false запрещена.

Набор Set в собственной fixture является только заведомо искусственной
реализацией интерфейса. Он **не эквивалентен Hunspell**: affix-правила, флаги,
регистр и исключения требуют отдельной совместимой реализации или проверенного
экспорта. Контроль no-PFX/SFX и ambiguity нельзя выкинуть ради удобства.
До этой интеграции не заявляем готовность реального словарного движка.

Нет сети, clipboard, IPC, файлового чтения или истории ввода в runtime-модулях.
Вызов облачного Claude — только разработка по публичному заданию, не обработка
набранных пользователем слов. Установка, реальные профили и системные клавиши
не затрагиваются; двойной Super остаётся согласованным ручным действием.

## Где ещё нет готового продукта

Синтетический набор проверяет правильность вычислений и безопасность соединения
компонентов. Он не разрешает выпуск старых словарей/weights и не заменяет
проверку false positives на независимом естественном вводе. Для ежедневного
browser-корректора остаются: полноценная словарная реализация с совпадающей
семантикой, отдельный допуск данных для packaging, integrity/provenance загрузки,
адаптер реального почтового/мессенджерного редактора и отзыв минимальных прав.
Терминальный milestone не закрыт браузерным прототипом.
