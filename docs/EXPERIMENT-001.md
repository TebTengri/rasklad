# Эксперимент 001: компактный RU/EN detector

Дата: 2026-11-10. Задачи SYS-231 и SYS-232. Код реализовал Claude Opus 5.5; Codex прочитал реализацию, запросил исправления и независимо собрал, проверил и запустил стенд. Методика и команды: [DETECTOR_EXPERIMENT](DETECTOR_EXPERIMENT.md). Полный агрегированный [JSON результата](results/experiment-001.json) содержит счётчики, пороги, хеши, размеры и времена, без списков слов и пользовательского ввода.

## Решение после первого прогона

Компактность и скорость подтвердились, пригодность к автоматической замене текста — ещё нет. Single-D и two-score восстановили одинаковое число слов и сделали одинаковые 5 ложных замен. Преимущество двух абсолютных оценок на этой проверке не доказано. Архитектура остаётся экспериментальной; никакой системный ввод к ней не подключён, параметры по умолчанию disabled.

Пороги после просмотра test не менялись. Не добавлялись исключения для пяти обнаруженных ошибок. Следующий независимый корпус должен проверять обобщение, включая код, имена, идентификаторы, неизвестные строки и неоднозначность, а не только воспроизводить этот holdout.

## Данные и разделение

Использован снимок LibreOffice/dictionaries c0865a85eb67dc377f2cf8e8fe2c4fa9e53f0dcb, en/en_US.dic и ru_RU/ru_RU.dic. Первичные уведомления прочитаны до скачивания; паспорт, хеши и полные notices находятся в [data/](../data/README.md). Допущен только локальный эксперимент; release_approved=false. Исходные файлы находятся в игнорируемом build/, производная модель сериализована только в памяти и не распространяется.

После lowercase и letter-only фильтрации: EN 47 828 типов, RU 146 229. Affix flags удалены, словоформы из .aff не разворачиваются. Все типы имеют одинаковый вес, естественных частот нет.

| Часть | EN | RU |
| --- | ---: | ---: |
| Train | 34 025 | 97 632 |
| Calibration | 7 323 | 29 912 |
| Test | 6 480 | 18 685 |

Разделение SHA-256 по первым трём каноническим клавишам сделано до wrong-layout augmentation; один ключ в обоих языках и обе его версии остаются в одной части. Проверено ноль пересечений ключей, слов и wrong-layout отображений между частями. Prefix grouping — только приближение к семействам, полной независимости лемм не доказывает.

Всего 103 ключа представлены в обоих словарях: 64 train, 24 calibration, 15 test. В test это 60 неоднозначных токенов после генерации обеих версий; они считаются отдельными safety negatives. В calibration нет таких токенов длины >=4, поэтому ограничение на неоднозначность здесь не получило содержательной проверки. В test восемь неоднозначных токенов длины >=4, обе статистические политики изменили ноль из них. Метки неоднозначности получены из полного набора словарей и являются oracle metadata, отсутствующей у будущего runtime.

## Качество на словарном holdout

Из основных метрик исключены неоднозначные случаи: 25 135 корректных и 25 135 wrong-layout токенов. Дополнительно проверены 60 неоднозначных случаев. Токены длины 1–3 всегда пропускаются n-gram и exact политиками; среди основных test-типов таких 375. Доля синтетических ошибок 1:1, поэтому precision в JSON нельзя переносить на обычный набор текста.

| Метод | Восстановлено из 25 135 ошибочных | Ложных замен из 25 135 корректных | Изменений неоднозначных |
| --- | ---: | ---: | ---: |
| Всегда оставить | 0 | 0 | 0 |
| Exact только train | 0 | 0 | 0 |
| Exact полный словарь* | 24 760 (98,51%) | 0 | 0 |
| Single-D | 23 921 (95,17%) | 5 | 0 |
| Two-score | 23 921 (95,17%) | 5 | 0 |

*Полный словарь заранее содержит test-слова. Это контроль покрытия известных слов, не доказательство обобщения или превосходства на незнакомом тексте. Exact только train получает нулевое покрытие по конструкции разбиения; это тоже не основание отвергнуть словари. Оптимизированные FST/DAFSA в этом опыте не реализованы.

Для слов длиной >=4 обе статистические политики восстановили 23 921 из 24 760 (96,61%). Все пять ложных замен относятся к корректным русским словам. Частота по основной корректной выборке: 5/25 135 ≈ 0,0199%, но выборка словарная и сгруппированная; это не оценка риска при реальном вводе и не гарантия редкости ошибок. Ошибок преобразования после решения Correct не обнаружено.

Пороги выбраны только по calibration при нуле ложных изменений и максимуме восстановлений: Single-D gap=2,5; two-score gap=2,5, minAlternative=-13, maxObserved=-9. На calibration обе политики восстановили 36 121 случай без ложных изменений; результат test показывает, почему ноль ошибок calibration не является гарантией. На test общий abstain rate для основных случаев: Single-D 4,81%, two-score 9,85%; решения Keep у two-score и Single-D также различаются.

## Размер и вычисления

Алгоритм: сглаженные add-alpha=0,5 log-оценки порядков 1/2/3, сумма весов (1,1,1), int8, scale=8. Это простой начальный вариант, не Kneser–Ney и не нейросеть. Средний log-score не является калиброванной вероятностью.

| Два канала весов | 88 270 байт |
| Сериализация с заголовком | 88 290 байт (86,22 KiB) |
| qCompress модели, storage reference | 28 901 байт |

| Обучение | 8 мс |
| Подготовка данных | 11 191 мс |
| Полный перебор порогов | 6 683 мс |
| Test | 145 мс |

CPU AMD Ryzen 5 7530U, x86_64, Qt 6.12.0, GCC 16.2.1, release -O2, один вычислительный поток. Тёплый путь canonicalize + score + decideTwoScore: p50 ≈ 0,681 мкс, p95 ≈ 1,271 мкс, p99 ≈ 1,694 мкс. Это квантили средних времён 32 повторений каждого из 2000 выбранных токенов, с накладными расходами таймера; не квантили одиночных нажатий клавиш. Системный ввод и межпроцессные задержки отсутствуют.

Один полный запуск занял около 19,12 с. Подготовка, обучение и калибровка — offline-этапы, не фоновая работа будущего приложения. Cold start, постоянный RSS и энергопотребление не измерены. Размер весов и сжатых файлов нельзя выдавать за расход оперативной памяти; whole-experiment RSS через rusage supervisor bubblewrap не установлен и не публикуется.

## Независимые проверки

- bin/test -silent: 160 тестов преобразования и 134 теста детектора/подготовки данных прошли.
- Полный перебор 131 072 сочетаний одиночного UTF-16 символа и source layout совпал с независимым XKB-эталоном: 66 допустимых символов для каждой раскладки.
- Независимая Python-реализация формулы на искусственной fixture дала ровно тот же SHA-256 всех 88 290 байт сериализованной модели: 56cdd8b44c12b034ac0bb3a47590c7f1e93a2149cbcb04f7513c5fcbad8f72b9.
- AddressSanitizer и UndefinedBehaviorSanitizer на отдельной проверке повреждённых заголовков, размеров, весов и enum не обнаружили ошибок. LeakSanitizer отключён: среда с ptrace его не поддерживает; это не проверка утечек памяти.
- Независимая Python-фильтрация совпала по числу типов, хешам списков, split counts и 103 общим ключам.
- CLI отказал без аргументов/манифеста, при подмене EN файлом RU, недопущенном статусе, неверном notice hash и traversal-пути. stdout при отказах пуст; содержимое файлов и путь-маркер в ошибках отсутствуют.
- Прогон и проверки CLI выполнены через bubblewrap в отдельном network namespace: смонтированы только /usr, проект read-only, временные /tmp, /dev и /proc. Домашний каталог и соседние проекты не смонтированы. Модуль распознавания не использует сеть, файлы, процессы, clipboard или системный ввод.

## Следующий критерий

Нужны независимо допущенные test-данные и заранее зафиксированные требования к ложным заменам/отказам. Проверить неизвестные строки и код, более длинные неоднозначные пары, реалистичную долю переключений и компактный exact-кандидат. Следующее сравнение проводить на новом holdout; результаты этого опыта не использовать как обещание безопасного автоисправления.
