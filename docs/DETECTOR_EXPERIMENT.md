# Offline-эксперимент детектора раскладки (SYS-232)

Стенд проверяет гипотезу: компактный n-граммный scorer по физическим клавишам отличает слово, набранное в своей раскладке, от слова, набранного в чужой. Это эксперимент над словарными типами слов, а не оценка качества продукта. Детектор не подключён к вводу и ничего не заменяет.

Первый проверенный прогон и его ограничения: [EXPERIMENT-001](EXPERIMENT-001.md).

## Состав

| Файл | Назначение |
| --- | --- |
| `src/ngramdetector.{h,cpp}` | Чистое ядро: канонизация, обучение, оценка, формат v1, политики решения. Без I/O, сети и логов. |
| `tools/detectordataset.{h,cpp}` | Разбор Hunspell `.dic`, детерминированное разделение, подсчёт утечек. Работает с байтами в памяти. |
| `tools/detectormanifest.{h,cpp}` | Разбор и проверка `data/sources.json`, безопасное разрешение путей уведомлений. |
| `tools/detector_experiment.cpp` | CLI: читает только явно переданные файлы, выводит агрегированный JSON. |
| `tests/detector/detector_tests.cpp` | QtTest на искусственных fixtures; внешние словари не нужны. |

## Запуск

Сборка и тесты: `bin/build`, `bin/test` (сначала `rasklad_tests`, затем `detector_tests`).

Словари скачиваются отдельно, вручную, в игнорируемый `build/experiment-data/` по URL и commit из `data/sources.json`. CLI сам сеть не использует.

```sh
build/tools/detector_experiment \
    --manifest data/sources.json \
    --en build/experiment-data/en.dic \
    --ru build/experiment-data/ru.dic \
    --json > build/detector-report.json
```

Все четыре аргумента обязательны. Коды выхода: `0` — отчёт выведен; `1` — отказ входных данных или манифеста; `2` — неверные аргументы; `3` — нарушена целостность (утечка между частями, пропущенные последовательности при обучении, недопустимая модель, неудачный round trip сериализации). При ненулевом коде JSON не выводится.

## Проверка манифеста (до разбора и обучения)

1. Манифест — обычный файл не больше 64 KiB, JSON-объект.
2. `schema_version` — целое 1; `status` = `approved-local-experiment`; `scope` = `local-experiment-only`; `release_approved` — логическое `false`; `commit` — 40 строчных hex.
3. `training_sources` — ровно два объекта, `en` и `ru`, без повторов. `sha256` и `notice_sha256` — 64 строчных hex; `bytes` — целое в `[1, 64 MiB]`.
4. Размер и SHA-256 переданного `--en`/`--ru` должны точно совпасть с манифестом.
5. `notice` — относительный путь под `data/notices/`, только `[A-Za-z0-9._-/]`, без `.`, `..` и пустых сегментов, до 200 символов. Корень — родитель каталога манифеста. Canonical-путь уведомления (после symlink) должен остаться внутри корня; файл не больше 1 MiB, его SHA-256 равен `notice_sha256`.

Любое несоответствие — отказ с сообщением без путей и содержимого. В отчёт попадают SHA-256 манифеста, статус, scope, upstream commit и SHA-256 файлов. Ошибки чтения `QFile`, превышение предела и изменение размера во время чтения тоже приводят к отказу.

## Метод

- **Разбор `.dic`.** Строгий UTF-8, один начальный BOM снимается, CRLF допускается. Число записей должно точно равняться заголовку: учитываются все строки после заголовка, включая пустые, кроме пустого хвоста после финального `\n`. Слово берётся до `/` или табуляции; запись из нескольких слов отбрасывается, поле вида `po:noun` — нет. Аффиксы не разворачиваются, `.aff` и частоты не используются. Остаются слова из букв языка длиной 1..32 в нижнем регистре; каждый тип учитывается один раз.
- **Канонизация.** Токен переводится в последовательность из 33 буквенных клавиш ru(default) с явно указанной исходной раскладкой. Регистр и Shift-уровень us-пунктуации нормализуются; токен не делится по пунктуации (`k.,jdm` = «любовь»). Цифры, дефис, `’`, combining marks, символы вне BMP и смешанная письменность отвергаются.
- **Разделение.** `SHA-256("rasklad-SYS-232-split-v1" || 0x00 || первые 3 клавиши)`, первые 8 байт big-endian mod 100: `[0,70)` train, `[70,85)` calibration, `[85,100)` test. Группа одна для обоих языков, поэтому EN-слово, его копия в ru и RU-слово на тех же клавишах всегда в одной части. Wrong-layout копии создаются после разделения. Найденная утечка ключей, слов или отображений прерывает запуск.
- **Модель.** Для каждого языка — unigram, bigram и trigram по алфавиту 33 клавиши + BOS + EOS, add-0.5, `round(8 ln P)` в `[-127, 0]`, веса (1,1,1). `S_L = raw_L / (8 (n+1))` — взвешенная log-оценка, не вероятность. Формат v1: 20 байт заголовка + 2 × 44 135 int8 = 88 290 байт. Модель сериализуется только в памяти; файлы модели не пишутся.
- **Политики.** Single-D (`D = S_alt − S_obs`) и две оценки с reject-регионом, см. `src/ngramdetector.h`. Токены короче 4 клавиш всегда получают Abstain. Тот же порог применяется к exact-baseline (train-only и полный словарь), поэтому сравнение честное.
- **Калибровка.** Перебор сеток от строгих порогов к мягким. Выбирается максимум восстановленных однозначных wrong-копий при нуле ложных исправлений на calibration (с учётом неоднозначных токенов, см. ниже). Test-часть в калибровке не используется. Если ничего не восстановлено, политика выключена.

### Неоднозначные ключи

Ключ неоднозначен, если есть в обоих словарях (например, набор клавиш — слово и в en, и в ru). Такие токены:

- остаются в обучении;
- в калибровке входят как **safety negatives**: любое Correct на них — ложное исправление, восстановлением не считается никогда;
- в оценке каждой политики показаны отдельно: `ambiguousChanged`, `unsafeChangesIncludingAmbiguous` (= falseCorrections + wrongCorrections + ambiguousChanged) и `ambiguousSafetyNegatives`. В precision/recall valid/wrong они не входят.

**Ограничение (oracle metadata).** Метки строятся по полным исходным словарям, включая test-слова; развёрнутый детектор таких меток не имеет. Так как группы разделения — префиксы ключей, неоднозначный ключ лежит в одной части для обоих языков, и метку можно получить из этой части. Неоднозначность со словами, которых нет ни в одном словаре, не обнаруживается.

## Ограничения

- Данные — словарные типы, а не естественный текст с частотами; оценочная смесь искусственная (1 valid : 1 wrong). Precision в отчёте — не precision в эксплуатации.
- Группировка по 3-клавишному префиксу — proxy семейства слов, а не доказанная непересекаемость лемм.
- Пороги — результат эксперимента, не production-значения; по умолчанию политики выключены.
- Короткие токены (1..3 клавиши) не решаются: отдельная модель отложена.
- Задержка измеряется тёплой, в одном потоке; холодный старт и RSS не измеряются.
- Источники допущены только для локального эксперимента (`data/sources.json`, `docs/DATA_POLICY.md`). Словари и производные таблицы остаются в `build/`; их выпуск не одобрен. Проверенный агрегированный отчёт без слов и весов опубликован отдельно в `docs/results/experiment-001.json`.
- Отчёт содержит только агрегаты и хеши: пути, исходные и ошибочно распознанные слова не выводятся.
