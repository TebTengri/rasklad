# Критическая сверка архитектуры: native Wayland

2026-11-14. Рецензенты: Claude Opus, Grok 4.7 и Gemini 3.8 Flash.
Передавались публичные технические сведения, без пользовательского ввода и
профилей. Локальные исходные ответы находятся в ignored build/architecture-council
и build/wayland-ime. Мнение модели — гипотеза для проверки, а не доказательство.

| Замечание | Решение и основание |
| --- | --- |
| Успех Sway не доказывает работу установленного Hyprland и Slack | Принято. Следующая развилка — точный compositor, затем отдельный клиент Slack. Другие reference backends пока не добавляем. |
| Между проверкой хеша и bind исполняемый файл могут заменить | Исправлено для нового Wayland runner: sealed memfd snapshots, ro-bind-data; guards проверяют неизменяемость и неправильный хеш. |
| Возможен ложный успех через GTK/D-Bus вместо Wayland | D-Bus input frontend исключён; introspection подтверждает отсутствие интерфейса. Нет DISPLAY/X server, Chromium запускается с Wayland text-input-v3. |
| Завершение вспомогательного процесса должно дожидаться выхода | Исправлено: ожидание своего virtual-keyboard child и ограниченное завершение; namespace уничтожается при выходе. |
| Сбой внутри Fcitx имеет широкий радиус воздействия | Риск принят к проверке, не к выпуску. В обоих изолированных transport-тестах дальнейший ввод продолжался; судьба текущего слова различалась. Это не гарантия для рабочего окружения. |
| Slack гарантированно ломает Undo/форматирование; известен его редактор | Не подтверждено. Требуется тест точной версии Slack; предположение об используемом редакторе не используем как факт. |
| В Hyprland есть риск serial/focus рассинхронизации | Остаётся открытым: source review не заменяет adversarial runtime test. Исправление в другом поле недопустимо. |
| Следует сначала уменьшить память ядра | Отложено: измерено около 56 MiB RSS Fcitx с ядром в reference-тесте; совместимость и корректность сейчас важнее оптимизации этого числа. |
| Проверка происхождения данных отсутствует | Не соответствует состоянию проекта: локальные входы закреплены хешами и сопровождаются provenance/notices. Разрешение на распространение проверяется отдельно. |

На следующих архитектурных развилках и перед live-интеграцией повторяем
независимую критику: безопасность, сохранность текста, совместимость, задержка,
память/CPU, лицензии и сложность сопровождения. Фиксируем разногласия и тест,
который способен их разрешить. Большинство голосов не заменяет измерения и
не доказывает глобально оптимальное решение.
