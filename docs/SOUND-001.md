# SOUND-001: короткий ретро-сигнал

SYS-223, 2026-11-12. Пожелание владельца: короткий ретро-звук в духе Omarchy. Реализован собственный синтез, компонент feedback, lazy player и диалог прослушивания. [Агрегаты](results/sound-001.json).

- 70 мс, PCM 48 kHz/16-bit/mono, 6764 байта. Два коротких тона 1174.66/783.99 Hz, ограниченные гармоники, плавная атака и затухание, нулевые крайние samples. Это собственный сигнал, не копия системного аудио Omarchy. Генератор `src/sounds/generate.py`, сторонних samples нет.
- «Звук → Прослушать», выключатель, RU/EN. Предпочтение действует в памяти до выхода. UI следует текущей теме; диалог проверен offscreen, включая русский узкий layout.
- QSoundEffect/выбор default output создаются только при запросе. Один встроенный qrc WAV, volume 0.45, один повтор, без внешних путей/URL, записи, микрофона, скачиваний, системной громкости и автозапуска. Отдельный Qt Multimedia модуль добавлен как установленная shared dependency, не bundled binary.
- `SoundFeedback::notifyLayoutConfirmed` — будущий C++ вход от backend. Нужны монотонные sequence IDs в пределах жизни компонента и известные разные before/after layouts. Unknown/invalid/unchanged/старые/повторные ID не вызывают звук. Выключенные/слишком быстрые события потребляются без последующего replay. Preview — отдельная явная команда. Сам компонент раскладку не наблюдает.
- При выключении queued cue отменяется, playing cue останавливается. Между запросами минимум 180 мс; pending — один, готовность после 300 мс не приводит к позднему воспроизведению. Загрузка/ошибка обрабатываются сигналами без waitFor*, processEvents или blocking timer. Нет detached процессов и бесконечного повтора.

## Проверка

606 Qt passed, 0 failed, 1 optional real-profile skip. Три новых unit cases проверяют фильтрацию подтверждений, mute/replay и coalescing через QSignalSpy, без player/audio devices. Новый UI case использует такой же fake output: диалог, явный preview, disabled state и смена языка; screenshots проверены визуально. PCM header/frame count/peak/endpoints проверены отдельно.

Отдельный probe с настоящим RetroSoundPlayer/QMediaDevices выполнен в bwrap без сети, host HOME, audio sockets и /dev/snd, с лимитами времени/CPU/address space. Вернул `no_output_refused=true`, exit 0, stderr 0: отсутствие выхода отрабатывается без падения. Стереосистема/динамики владельца не использовались. Восприятие тембра и фактическая слышимость на реальном устройстве требуют прослушивания владельцем; уровень в dBFS не равен громкости динамиков.

## Граница готовности

В текущем приложении работает кнопка прослушивания и mute; **автоматического звука при системном переключении ещё нет**, поскольку backend раскладки не подключён. Выбор направления ручного предпросмотра и Apply не выдают ложное событие системной смены. Компонент готов к вызову после будущего подтверждения реального изменения; это не добавляет перехвата клавиш или права работать с seat.

Qt API сверено по [QSoundEffect 6.12](https://doc.qt.io/qt-6/qsoundeffect.html). Системные настройки и соседние проекты не менялись. Тема/язык по-прежнему читаются существующим механизмом только на чтение. Код/аудио сторонних проектов не переносились; лицензия своего релиза отдельно не выбиралась.
