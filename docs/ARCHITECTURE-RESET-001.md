# Пересмотр системного ввода: preedit вместо внешней замены

Дата: 2026-11-14. SYS-242 / SYS-243. Статус: архитектурная гипотеза, не готовый Slack backend.

Владелец запросил совместный разбор доступными моделями. Независимый одинаковый публичный brief без пользовательского текста разобрали Claude Opus 5.5 (Claude Code, инструменты отключены), Gemini 3.8 Flash High (Antigravity, plan/sandbox, пустой workspace) и дополнительный агент Codex (read-only ревизия upstream). Codex сопоставил выводы с первичными API. Для Grok установлен закреплённый Cursor CLI 2026.11.11-b912975; владелец завершил штатную авторизацию. Grok 4.7 High и Medium не завершили ответы за пределы 180/100 секунд; заключительный Grok 4.7 Low дал финальный краткий вердикт в Ask/sandbox с пустым workspace. Сокращённый вопрос Grok отличался от исходного brief: требовал оценить конкретную preedit-гипотезу. Поэтому это дополнительная проверка, а не четвёртое независимое полное исследование. Токены редактора не извлекались.

Grok поддержал preedit/commit и предложил реальный критерий отказа: буквенные commit до Space, пропавший preedit, дубли слова/пробела. Его заявление о частоте проблем Slack/Electron и формулировка «единственный допустимый путь» не подтверждены наблюдением/исходниками и не принимаются как факт. Все четыре участника рекомендуют кандидат IME; никто не доказал его работоспособность в exact Slack.

## Решение для следующего доказательства

Рекомендуемый кандидат: addon Fcitx5, который удерживает одно текущее слово в client preedit и при Space передаёт результат одним commitString. Изначально прямой toolkit IM module и приватный D-Bus, без второго input-method-v2 клиента в рабочем сеансе. Не читать/удалять уже принятый приложением документ. Существующие detector/router сохраняются, но не подключаются до доказательства транспорта.

Это не универсальный перехват: события доступны только подключённым к Fcitx приложениям. PreInputMethod watcher позволяет работать перед выбранным keyboard engine, однако соответствие системной раскладки/keysym и корректный passthrough должны быть проверены. Установленные Fcitx5/GTK/Qt модули уже есть; установка самого addon и изменение рабочего сеанса ещё не выполнялись.

Первичные источники:
- https://fcitx-im.org/wiki/Develop_an_simple_input_method/en — preedit, key filtering, commit и поведение focus-out.
- https://raw.githubusercontent.com/fcitx/fcitx5/master/src/lib/fcitx/instance.h — watchEvent / PreInputMethod / inputMethodEntry.
- https://raw.githubusercontent.com/fcitx/fcitx5/master/src/lib/fcitx/inputcontext.h — commitString / updatePreedit.
- https://raw.githubusercontent.com/fcitx/fcitx5/master/src/frontend/waylandim/waylandimserverv2.cpp — Wayland frontend использует стандартный IM keyboard grab и virtual keyboard.
- https://fcitx-im.org/wiki/Using_Fcitx_5_on_Wayland/en — Electron/XWayland через GTK module; Wayland через text-input. Это общее upstream руководство, не доказательство exact Slack.

## Что не принимаем как доказанные гарантии

Совпадение рекомендаций моделей — основание для эксперимента, не подтверждение работоспособности. Gemini ошибочно обещал сохранение процесса Fcitx после падения in-process addon: crash addon способен уронить весь Fcitx. Также не подтверждены автоматический fail-open, отсутствие focus races, точное native Undo и корректность всех password hints. Один отрицательный AT-SPI snapshot не доказывает невозможность accessibility вообще. Не объявлять точный Slack composer ProseMirror по старому notice.

Стандартный IME grab ограничен протоколом ввода и не равен root/evdev/input-group доступу. Наш ранний полный запрет любых grab/virtual keyboard нельзя выдавать за совместимый со стандартным Fcitx Wayland frontend. Host activation такого пути требует отдельного конкретного решения и проверки. Прямой toolkit module исследуется первым для обхода этого relay.

Preedit меняет UX: приложение ещё не хранит исходное слово, поэтому native Undo не обязан восстанавливать латиницу. Сбой IME может потерять незакоммиченное слово; это риск, а не решённая гарантия. Mentions, code, Enter/Tab, редакторские hotkeys и focus-out могут взаимодействовать с composition. App allowlist не доказывает prose/secret контекст конкретного поля.

## Ближайшая проверка: транспорт, не детектор

1. В отдельном HOME/XDG/runtime/D-Bus запустить Fcitx только с проверенными direct frontend modules. Рабочий seat, обычный профиль Slack и системные настройки не подключать. Проверить точные имена frontend и настройки по установленной версии до запуска.
2. Использовать реальное установленное приложение (первый доступный Chromium с одноразовым профилем через изолированный X11/GTK IM транспорт, либо штатный GTK/Qt редактор). Локальная fixture может наблюдать IME события, но считается только доказательством транспорта, не поддержкой Slack.
3. Минимальный addon содержит только фиксированное синтетическое правило ghbdtn -> привет. Полный словарь/модель на этом этапе не нужны.
4. Условия успеха: видимый preedit; ровно один ожидаемый commit на Space; следующий символ сохранён; Backspace/selection/modifiers работают; password/sensitive не буферизуются; после смены поля commit не уходит в другой контекст; native Undo/Redo проверены фактически; после остановки Fcitx обычный ввод восстановлен. Crash отдельно измеряет сохранность текущего слова. Не отправлять сообщения.
5. Затем exact Slack в добровольно введённом тестовом черновике без отправки, с Undo, bold, link, mention, code. Только этот шаг может подтвердить native Slack compatibility. Если direct IM канал не работает — не продолжать разработку этого backend вслепую.

## Ограничение объёма

До первого настоящего IM commit не расширять ядро, словари, browser adapters или UI. DoubleSuper для уже принятого слова — отдельная нерешённая задача. Термinals и остальные приложения не объявляются поддерживаемыми по результату Slack. Не менять на живом хосте IME/flags/config ради исследования без конкретной согласованной процедуры.

## Исполнимый критерий продолжения

Следующий implementation PR должен доказывать именно transport: addon загружается из project-local каталога, получает события только отдельного приложения, отображает preedit и коммитит синтетический результат. Приёмка не засчитывается по unit tests своего автомата. Сначала нужен реальный frontend/client обмен. Эксперимент ограничен одним рабочим днём; если транспорт недоступен, публикуется конкретная причина и выбирается fallback, а не новый detector/UI.

Условия сбоя описываются раздельно: (1) выключение addon, (2) нормальное завершение IME, (3) crash всего IME. Нельзя обещать fail-open по проверке только (1). Password тест измеряет отсутствие буферизации/исправления addon, а не утверждает, что никакой компонент IME никогда не видел события. Непроверенные hints остаются ограничением.

Исследование не меняет лицензирование собственного кода MIT. Fcitx и IM modules имеют собственные условия; до копирования/линковки нужно закрепить точные исходники и SPDX/notice каждого компонента. Ссылка на master здесь — исследовательский ориентир, не lockfile и не разрешение распространять зависимость.

## Предварительная проверка установленной среды

Установлены Fcitx5 5.1.23, fcitx5-gtk 5.1.7 и fcitx5-qt 5.1.16; pkg-config видит Core/Utils 5.1.23. В установленных headers подтверждены watchEvent/PreInputMethod/inputMethodEntry, commitString/updatePreedit и флаги Password/Sensitive/NoSpellCheck/Terminal/Preedit. Это API availability, не работающий addon.

Chromium и dbus-run-session доступны. Xvfb, weston и stock GTK/Qt GUI editor из короткого проверенного списка не найдены в PATH. Поэтому полностью изолированный direct X11/GTK эксперимент ещё требует подготовить display transport; headless Chromium без настоящего IM frontend не считается заменой этому доказательству. Не выдавать «зависимости Fcitx установлены» за «весь стенд уже готов».

## Граница PoC и продуктового решения

Direct GTK/Qt — доказательство транспорта, не рекомендация переносить живой Slack с native Wayland на общий XWayland. Межклиентская изоляция общего X11 слабее; такой переход ради обхода не выполняется. Предпочтительный продуктовый кандидат — уже действующий Fcitx и native Wayland frontend после проверки конкретного relay/focus lifecycle и стандартного IM grab/forward. Избыточный полный запрет стандартного IM grab был нашей формулировкой, его нельзя приписывать владельцу как отдельное явное требование.

Нет стандартного Fcitx признака «prose / code / mention». Поэтому generic Slack autocorrect со строгой семантической защитой не доказан даже при успешном IM commit. Ограниченный PoC допускает только явно выбранное владельцем тестовое prose поле с синтетическим текстом; для продукта нужен подтверждённый источник семантического контекста либо явно согласованный ограниченный охват. Нельзя одновременно объявлять fail-closed на unknown и исправлять все неизвестные поля.

CDP Input.insertText / imeSetComposition без настоящего Linux frontend не засчитываются: это тест renderer composition, а не Fcitx roundtrip.
