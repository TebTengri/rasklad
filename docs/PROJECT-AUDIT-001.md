# Ревизия безопасности, лицензий и ресурсов rasklad

Дата: 2026-11-12. Проверил Codex независимо от реализации Claude. База: `9a86c77461e24d930bf75d6de9665b62ac4ec7b6` (PR #11), плюс новый developer-стенд INPUT-LAB-002 и исправления этой ревизии. Область: только rasklad; соседние проекты не просматривались. Агрегаты: [project-audit-001.json](results/project-audit-001.json).

## Вывод и границы

В просмотренных путях собственного приложения не обнаружены сетевой listener, удалённое управление, выполнение текста как команд/QML/HTML, чтение других окон, глобальный перехват, фоновое чтение clipboard или сохранение истории. Это результат ограниченной статической ревизии и перечисленных испытаний, а не доказательство отсутствия всех уязвимостей, бэкдоров или нарушений прав.

Текущий GUI остаётся ручным предпросмотром. Он не является sandbox: работает с обычными правами пользователя. Процесс того же UID, root, скомпрометированная библиотека/Qt plugin, IME, accessibility и clipboard manager не изолированы этим приложением. Отсутствие собственных сетевых вызовов не равнозначно системному запрету сети; отдельный контрольный запуск ниже выполнен с таким запретом.

**К автоматическому системному вводу и бинарному выпуску проект пока не допущен.** Нужны подтверждённый безопасный backend, лицензия собственного кода, release-допуск данных и оформление зависимостей/упаковки.

## Проверенные поверхности

| Поверхность | Наблюдение и ограничение |
| --- | --- |
| Запуск и команды | `main.cpp` открывает только встроенный `qrc:/Main.qml`; неизвестные аргументы отклоняются. В runtime исходниках нет QProcess, system/popen/exec, QNetwork/собственного socket API. Developer-инструменты запускают явно заданные процессы отдельно |
| Текст | QML редакторы и текстовые подписи plain text. Apply требует актуального snapshot; старый ответ worker не заменяет новую редакцию. Сохраняются текущий текст, preview и одна Undo в RAM |
| Clipboard | Собственный writer только записывает по команде. Стандартные Copy/Cut/Paste — явные действия. PRIMARY ограничен до создания GUI; при оставшейся capability запуск редактора отклоняется. Это зависит от версии Qt и не защищает от внешнего clipboard manager |
| Файлы | Тема/язык читаются ограниченно, без команд и опроса. Профиль включается явно, проверяет размеры/SHA-256/паспорта/notices и symlink-компоненты. Проверки путей и хешей не устраняют TOCTOU-подмену другим процессом владельца |
| Hunspell | Только закреплённые локальные данные, без inference-сети/загрузок. Проверка загруженной библиотеки выполняется уже после dynamic loader; парсер C не изолирован отдельным процессом |
| Очередь/нагрузка | Один worker, не больше одного выполняющегося и одного ожидающего запроса; новый заменяет ожидающий. Токен/документ ограничены, нет фонового обучения и таймера распознавания. Shutdown ждёт текущий вызов provider |
| ELF защиты | Текущая Linux-сборка: PIE, NX stack, RELRO/BIND_NOW; qmake добавляет stack protector strong и release FORTIFY_SOURCE=3. Это смягчения эксплуатации, не изоляция процесса |
| Системный ввод | Нет установки, автозапуска, root/setuid, input-группы, udev, evdev/uinput и рабочего IME backend. INPUT-LAB-001 использует только свою socketpair |

Просмотрены main/options, QML, controller/worker, clipboard/bootstrap, профиль/проверка файлов, Hunspell adapter, bounded model/lexicon readers, qmake/run/build и subprocess-пути developer tools. Это не построчная формальная верификация всего кода и не аудит реализаций Qt/Hunspell/kernel.

## Находки и действия

| Находка | Статус |
| --- | --- |
| Новый nested runner мог перезаписать существующий hard-linked config через truncate | Исправлено до допуска: уникальный private run directory, `O_EXCL`, тест сохранности hard-linked файла. В `main` такой runner ещё не был выпущен |
| Runner мог считать сокет признаком готовности уже завершившегося процесса или запуска без подтверждения bwrap | Исправлено: сначала exit check, отдельная проверка корректного info JSON; тесты stale socket/no info |
| Runner скрывал неудачный reap после SIGKILL или отказ удаления run directory | Исправлено: отдельный `cleanup_failed`/код 14; успешная очистка не заявляется. Проверены mock отказы ожидания и удаления |
| Параллельная сборка занимала все доступные ядра | По умолчанию два задания в `bin/build` и `bin/test-input-lab`; явный `RASKLAD_BUILD_JOBS=1..64` для разработчика |
| Предел текста проверяется после поступления текста в Qt TextEdit | Открытое ограничение доступности: 65 536 UTF-16 — предел принятого документа, не верхняя граница пика heap/clipboard/IME во время огромной вставки. Сверхбольшие/враждебные paste нагрузки здесь не испытывались |
| Старые developer profiling/evaluation helpers содержат subprocess без общего wall timeout/ограничения вывода | Открыто: эти CLI запускаются вручную на доверенных локальных данных и не входят в приложение. Не считать их sandbox для произвольной программы; перед расширением на недоверенные probes нужен отдельный supervisor |
| Устаревший IM commit в Hyprland source path | Production blocker SYS-223; модель воспроизводит порчу текста, реальный compositor/client race ещё не проверен. Клиентская сверка перед отправкой не закрывает гонку после отправки |

## Репозиторий и секреты

- На базе PR #11: 215 tracked files; словарей `.dic/.aff`, corpus TSV и model/weights файлов среди них нет. В `build/` находятся локальные данные, и это не публичный дистрибутив.
- Проверены 286 уникальных исторических Git blobs (самый большой 1 385 056 B; пропущенных по лимиту 16 MiB нет). Сигнатуры private key, GitHub/AWS/Anthropic/OpenAI credentials и credential URL: 0 совпадений. Значения совпадений никогда не выводятся. Это ограниченный набор сигнатур, без entropy scan; он не доказывает отсутствие любых секретов.
- Read-only GitHub проверка: public; `main` требует PR, admin enforcement включён; force push/deletion запрещены; внешние approval не требуются (0). Code review Claude/Codex — наш процесс, а не требование независимой GitHub approval.
- Actions выключены; secret scanning и push protection включены; Dependabot security updates выключены. Это не автоматическое покрытие CVE для C++/qmake и системных Qt plugins. Настройки этой ревизией не менялись.

## Зависимости и лицензии

Инвентаризация и release-обязанности: [THIRD_PARTY](../THIRD_PARTY.md). 15 закреплённых пар notice path/hash в паспортах совпали. MIT XML совпадает побайтно с источником; copyright/permission text сохранён полностью. Источники сравнительных проектов не копировались; выпуск словарей и производных weights по-прежнему запрещён текущим локальным допуском. Лицензия собственного кода ожидает выбора владельца.

Установлены Qt base `6.12.0-3`, declarative `6.12.0-2`, wayland `6.12.0-1`, Hunspell `1.7.5-1`, wayland `1.26.0-1`, bubblewrap `0.13.1-1`. ELF приложения содержит QtNetwork как зависимость стека Qt, несмотря на отсутствие собственных network API; наличие библиотеки само по себе не означает сетевую активность.

Точечная сверка [официального списка Qt advisories](https://wiki.qt.io/List_of_known_vulnerabilities_in_Qt_products): CVE-2026-116337 относится к HTTP response resource consumption, CVE-2026-105924 — к CBOR→JSON; соответствующих операций в просмотренных путях приложения нет. QtWebSockets, Qt3D, QtHttpServer и Qt5Compat не заявлены в runtime target. Это анализ доступности известных путей, а не полный CVE scan всех транзитивных зависимостей. Наличие исправлений в фактически установленных бинарниках не подтверждено; номер пакета с `-3` сам по себе этого не доказывает. Перед выпуском нужен актуальный SBOM/patch review. Система не обновлялась этой проверкой.

## Ресурсы и испытания

Новый замер: собственный GUI, пустой документ, 6 с, offscreen/software, `bwrap --unshare-all`, без сети, host HOME/runtime/GPU/input, readonly `/usr` и бинарник. Actual app PID наблюдался через private `/proc` каждые 20 мс, приоритет nice +10, 1 GiB address-space cap, CPU cap 5 с. Это отдельный тестовый процесс, не изменение лимитов рабочего приложения или ОС.

- 293 samples; peak/last RSS 65 580 KiB ≈64,0 MiB. RSS включает shared pages; это не добавочная физическая RAM.
- За последние 1,977 с CPU счётчик не увеличился (разрешение ticks, не обещание постоянного 0% CPU).
- Ошибок stderr нет. После измерения процесс штатно остановлен тестовым SIGTERM. Бинарник около 333 KiB; Qt и данные в этот размер не входят. Дистрибутив не собирался.
- Ранее измеренный optional profile: около 100 MiB peak, см. [MVP-001-REVIEW](MVP-001-REVIEW.md). В этом аудите профиль заново не измерялся. GPU/native render, активная печать, огромные вставки и end-to-end автозамена не измерены.

Два первых тестовых запуска завершились SIGXFSZ: мой слишком строгий `RLIMIT_FSIZE=1 MiB` распространялся и на Qt буферы/memfd, не только на обычные файлы. После исправления тестового cap до 64 MiB прогон успешен. `coredumpctl` подтвердил `/lab/rasklad --language en`, сигнал 25 и `Storage: none`; пользовательский текст не вводился, core memory не извлекалась. Это дефект настройки измерения, не доказанный сбой рабочего GUI. Системные crash notifications не отключались.

Проверки: 602 Qt passed / 0 failed / 1 optional-profile skip; 30 INPUT-LAB-001 passed; 22 mocked runner test passed. Последние проверяют safety/cleanup-пути, но не доказывают безопасность bwrap/kernel. Прошлый ASan/UBSan/LSan прогон 30 C++ wire tests остаётся применимым к неизменённому C++ коду; новый runner — Python.

## Реальный изолированный композитор

[INPUT-LAB-002](INPUT-LAB-002.md): host preflight успешен, config `--verify-config` в sandbox вернул 0. Единственный smoke: sandbox запущен, до наблюдения сокета процесс завершился с кодом 134 за ≈102 мс; SIGABRT, core не сохранён. Точная причина не установлена: renderer/backend без GPU и memory cap остаются гипотезами. Host Hyprland продолжал работать; run directory удалён после reap. Физический доступ и GPU не добавлялись, повторного запуска с ослаблением границ нет. Автоисправление, парольные поля и матрица приложений этим не проверены.
