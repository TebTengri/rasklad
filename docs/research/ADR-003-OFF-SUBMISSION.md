# Отключение: локальное завершение и доставка — разные результаты

Статус: принято для LAB, 2026-11-16. Задача SYS-246.

При Off немедленно запрещаем новый capture/correction. Для существующей
composition при свежем совпадении приложения/контекста/epoch отправляем
исходное слово один раз обычным IME commit, освобождаем собственный buffer
и preedit. `Result::Submitted` означает завершение локального владения после
попытки отправки; он НЕ подтверждает принятие текста приложением. При потере
права записи — defer без отправки, перенаправления или повтора.

Причина: void Fcitx commit и Wayland done не дают приложению-корректору receipt
конкретного слова. Бесконечное хранение original не обеспечивает восстановление,
но оставляет незавершённый preedit; повторная отправка может дублировать текст.
Обычный IME путь уже работает с однократной отправкой без такого receipt.
Отдельный Unknown/confirmed-receipt контракт остаётся для адаптеров, у которых
есть настоящий наблюдатель результата. Производственный receipt не подделываем.

Независимый агент предложил отделить release локального владения от delivery,
после неудачного опыта с требованием trusted compositionend. В Chromium 155
контролируемый native путь дал trusted input insertCompositionText и untrusted
compositionend. Это не позволяет использовать isTrusted как универсальный ack.
Первый опыт намеренно остался FAIL; новый контракт не объявляет его успешным.

Порядок операций: snapshot original и lifetime watch; в InFlight до callback;
локально убрать buffer/preedit ownership; один commit; пустой preedit уведомить
только если контекст жив, в фокусе и shared epoch не изменился. После callback
не обращаться к старому LabState. Result::Submitted закрывает controller лишь
после возврата внешней операции. Release поглощённых клавиш ещё дренируется.

Для closed E2E есть отдельная сборка `tools/fcitx_disable_lab.pro` и явный
`--disable-suite`. Только эта сборка обрабатывает синтетический F12 при private
fixture flag. По умолчанию addon не содержит этой ветки; никакой пользовательской
клавиши или настроек не добавлено. Новый DBus setter/receipt endpoint не нужен.
Список доступов sandbox не расширен. F11 receipt trigger удалён до публикации.

E2E устанавливает активную composition в собственном textarea, вызывает Off,
проверяет свежие события и точный original, повторяет Off без дубля, отменяет
именно original через native Undo, затем проверяет raw word+Space без новой
composition. DOM не меняется скриптом во время измерения. Это behavioral proof
в конкретном owned Sway/Chromium, не аутентификация receipt и не универсальная
гарантия доставки. Фокус/уничтожение дополнительно проверяются actual SDK
memory tests; при смене epoch старое empty-preedit уведомление не отправляется.

Перед пользовательским режимом нужны настройка Off для всего приложения
(а не только одного InputContext), прекращение лишних подписок и проверка
на допустимом реальном приложении. No UI/installation/live Slack enabled.
