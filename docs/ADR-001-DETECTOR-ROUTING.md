# ADR-001: локальный маршрутизатор исправления раскладки

Статус: **принято для первого алгоритмического профиля и manual-preview MVP**. Desktop auto-input этим ADR не включается. Дата: 2026-11-11, SYS-238; реализация пользовательского MVP — SYS-239, доказательство безопасного input context — SYS-223.

## Решение

Основа — **полноценный локальный морфологический словарь + подтверждение существующей квантованной n-gram моделью**. Результат содержит Keep/Correct/Suggest/Abstain и reason codes. Короткие/неподдерживаемые и неоднозначные случаи могут остаться без автоматического исправления. Предыдущие слова не являются обязательным условием Correct; rolling context/history buffer в первом MVP не нужен.

Начальный пользовательский инструмент — собственное окно Qt Quick: пользователь вводит/вставляет текст, выбирает направление us↔ru, видит отдельный preview, явно применяет/копирует результат и может отменить. Прямое ручное преобразование вызывает чистый convertLayout и не обязано угадывать намерение через словарь. Исходный текст сохраняется до явного действия. Исследовательские CLI/TSV не используются для обработки текста пользователя.

## Точная таблица автоматического ядра: safeConfirmed

Порядок правил обязателен. Snapshot поступает только из разрешённого источника; отсутствие надёжных метаданных не заменяется догадкой по имени окна.

| Условие | Решение |
| --- | --- |
| Защищённое поле, кодовый контекст, неизвестный источник/фокус/layout или устаревший snapshot | Нет автоматического действия; неизвестный/защищённый поток не передавать в скрытый текстовый буфер |
| Неизвестная/неподдерживаемая keymap, unsupported token, длина<4 или>32 canonical keys | Abstain |
| Текущий вариант принят полным словарём своего языка | Keep, независимо от противоположного слова, модели и соседних слов |
| Общий ambiguity guard сработал | Abstain, автоматическая замена запрещена |
| Текущий вариант не принят, преобразованный принят другим полным словарём, twoScore==Correct | Correct-кандидат |
| Словарь и модель расходятся, либо оба словаря не знают слово | Abstain в автоматическом профиле; отдельный канал предложения по явному запросу |

Параметры twoScore остаются зафиксированными: minAlternative−13, maxObserved−9, gap2.5, target>=4. Это сравнительные n-gram scores, **не вероятности/проценты уверенности**. Новая нейросеть и online-learning не добавляются.

Ambiguity guard в проверенном профиле — stemBoth OR noPfxSfxControlBoth OR fullBoth. Full-both уже сохраняется observed-hit правилом, но остальные части нельзя молча удалить. Для точного воспроизведения текущий provider держит full/control Hunspell пары, stem-index и model. Компактный индекс пересечения или удаление control engines — отдельная оптимизация с equivalence tests, а не предполагаемая бесплатная замена правил.

## Предложения и роль контекста

Отдельный запрос пользователя может включать профиль hybrid: словарная альтернатива при несогласии модели или model-only альтернатива при miss обоих словарей возвращается как кандидат для preview. **Suggest никогда не применяется автоматически**. В manual/preview режиме даже внутренний Correct показывается до явного Apply; явное преобразование направления доступно также для словарно неоднозначного текста.

Пассивные всплывающие предложения в первом UI выключены. Исследовательский contextHybrid прошёл отдельный proposal-screen 006, но ни UX/утомление, ни реальная доступность безопасного поля не проверены. Такой pass означает возможность дальнейшего opt-in испытания, не включение уведомлений самовольно.

Обязательный script-context gate отвергнут: в опыте 006 он не предотвратил ни одной дополнительной ошибки, потерял большую часть одиночных исправлений и все burst-исправления. Фильтр contextHybrid также не уменьшил наблюдавшиеся false suggestions (0→0), но оставил 81,72% полезных предложений hybrid. Для первого MVP контекст не нужен ни как разрешение auto, ни как обязательный фильтр ручных кандидатов. Будущий обучаемый context scorer требует отдельной гипотезы/оценки, не меняет это решение автоматически.

## Почему выбран подтверждающий профиль

В опыте 006 safeFull восстановил 16 821 из 17 079 обычных подходящих ошибок (98,49%), safeConfirmed — 15 947 (93,37%); у обоих ноль наблюдавшихся ложных автоматических замен. Плата подтверждения — 874 пропущенных исправления для single и столько же для burst, в целом 5,12 процентного пункта. Максимальная языковая потеря 7,79 п. п. укладывается в заранее заданный предел 10 п. п. Для RU это 90,61% вместо 98,40%; для EN — 97,50% вместо 98,63%. Цена показана явно: full-профиль не объявлен хуже по наблюдавшимся ошибкам 006.

Выбор консервативный: опыт 003 показал случаи, где подтверждение уменьшило unsafe 5→0, тогда как 004/006 не продемонстрировали дополнительного уменьшения уже нулевых/малых ошибок. Guard в опыте 006 строже старого raw baseline 003, поэтому старые 5→0 не выдаются за точный эффект именно нового router. Это инженерный приоритет сохранения текста с измеренной ценой покрытия, не доказательство универсального превосходства модели.

006 — новые документы того же переводного технического домена, не чат; single/burst corruption синтетическая, safe-field/layout metadata oracle. Ноль ошибок на 17 293 eligible valid occurrences / 4742 wordtypes не сертифицирует частоту ≤1/10 000. Из архитектурного выбора не следует разрешение менять чужие приложения.

## Компоненты и границы

1. **Input adapter** создаёт immutable snapshot только для разрешённого текста: target, known fixed us/ru layout, document/field epoch, revision, span. Unknown/protected events инвалидируют transient state без накопления текста.
2. **Tokenizer/converter** — чистые bounded функции. Фиксированная ANSI us-basic/ru-default пара; custom keymaps/compose/AltGr и происхождение одинаковых символов требуют отдельного решения. Ручной preview указывает направление явно.
3. **Local data provider** загружает проверенные immutable dictionaries/model один раз; membership/ambiguity/scores предоставляются pure DecisionRouter через интерфейсы. Один processing owner/engine set, без конкурентного обращения к mutable provider state. Пользовательский словарь/адаптация не включены автоматически.
4. **DecisionRouter** не выполняет I/O, сеть, процессы и применение клавиш. Возвращает кандидат/action/reason/snapshot epoch. Scorer нужен после быстрых guards и словарной проверки кандидата; source-hit не требует принятия решения по модели.
5. **Executor** отдельно проверяет, что field epoch/revision/selection/text span всё ещё совпадают, контекст разрешён и операция обратима. Изменение фокуса/документа/ввода отменяет план. В owned preview pane Apply/Undo выполняются как одна видимая операция; global replay/uinput этим контрактом не разрешены.
6. **UI** показывает preview и явные Apply/Copy/Undo. Причины можно объяснять словами; технические scores/файлы словарей не становятся пользовательским сценарием. Нет фонового чтения clipboard или других окон.

Production core выделяется из tools/routerpolicy по семантике safeConfirmed с regression tests против зафиксированных действий; runtime не запускает research CLI и не пишет features/labels. В research файлах лежат лицензированные тестовые тексты, а не допустимый формат логов пользователя.

## Ресурсы и данные

В проверенном provider-профиле raw/serialized assets: full .dic+.aff — 4 099 394 B, control .aff — 1622 B, stem pair — 1 200 379 B, model — 88 290 B, суммарно 5 389 685 B без notices/library/бинарника. Это размеры файлов, не RAM. Hunspell shared library отдельно 546 936 B; стандартные Qt/system dependencies не оценивались как размер дистрибутива.

Измеренный свежий process с full+control+stem+model и одним нейтральным токеном дал peak 42 444 KiB ≈ 41,45 MiB, wall ≈ 0,162 с. Kernel rusage относится именно к единственному worker, не bwrap/Python supervisor; включает source verification/loader и старый полный stem-index. RSS включает shared pages и не равен добавочной памяти системы. OS page cache не очищен, один observation; GUI/steady-state/end-to-end keystroke latency не измерены. [Полный профиль](results/experiment-006-provider-resource.json). Сокращение provider stack пока не предполагается.

Работа проектируется по событиям/границам слов, без постоянного polling. Модель CPU-only, inference без сети и фонового обновления. В manual forced-conversion режиме словари/weights вообще не обязательны. GUI и точный production provider профилируются после сборки, до обещаний нагрузки.

Все исходные/производные dictionaries/weights пока допущены **только к локальному эксперименту**. До упаковки/выпуска нужен отдельный допуск package/data licenses с полными notices и пометками изменений; этот ADR его не заменяет. Пользовательский ввод не становится обучающим набором, cache/history/телеметрией или cloud prompt. Диагностика — без слов/токен-хешей/clipboard содержимого; персонализация только отдельным явным opt-in проектом.

## Последовательность реализации

- SYS-239: owned QtQuick manual-preview MVP, pure production core с reason codes, тесты Apply/Undo/revision races, без global input/settings/install/autostart.
- SYS-223: отдельно подтвердить доступный безопасный input mechanism, password/unknown-field handling и возможность атомарной отмены; если контракт не обеспечивается, desktop остаётся manual/preview.
- После этого — явный opt-in limited auto profile safeConfirmed в проверенных контекстах с доступной отменой, отдельные реальные испытания. Прохождение 006 не включает его автоматически.

Решение принято; повторные эксперименты нужны для изменения этой схемы/источников/порогов, а не вместо реализации первого MVP.
