# Данные и автономная работа детектора

Требования владельца, зафиксированные для SYS-230. Это политика проекта, не заключение о правах на конкретный ещё не выбранный набор.

## Работа приложения

- Детектор работает без сети: не обращается к API, удалённым словарям, облачным моделям и базам данных.
- Нужные проверенные данные поставляются с выбранной версией пакета. Нет скрытой загрузки модели при первом запуске или фоновой синхронизации.
- Обновления — отдельное явное действие. Недоступность сети не меняет результат распознавания.
- Пользовательский ввод не является телеметрией или источником обучения. Контекст допускается только в памяти, с коротким сроком жизни и сбросом при изменении поля/сеанса.
- Пользовательские исключения — отдельное явное действие; без автоматического накопления истории. Слова в исключениях тоже могут быть чувствительными, поэтому их не отправлять и не публиковать.

Облачная консультация Claude по публичному устройству алгоритма используется при разработке и не является зависимостью работающего детектора. Она не получает реальный ввод пользователя.

## Допуск данных

До скачивания набора для обучения, включения словаря или использования готовых weights определить применимые условия. Для распространения требуется заполненный паспорт артефакта и выполненные обязательства. Если разрешение или происхождение неясны, набор не допускается; публичный URL и слово open-source сами по себе не достаточны.

Для каждого train/calibration/test источника и полученного model/dictionary артефакта фиксировать:

| Поле | Что должно быть записано |
| --- | --- |
| Идентичность | Автор/издатель, URL, дата, версия/commit, SHA-256 конкретных файлов |
| Условия | Полный текст лицензии, область действия, отдельные лицензии компонентов/корпуса/weights |
| Применение | Разрешены ли выбранные обучение, модификация и распространение; какие обязанности выполним |
| Происхождение | Исходный корпус и его источники, а не только лицензия скрипта генератора |
| Преобразования | Фильтрация, нормализация, генерация словоформ, хеширование, обучение, квантование; воспроизводимые команды/seed |
| Разделение | Train/calibration/test, документы/семейства слов и защита от утечки между наборами |
| Публикация | Требуемые NOTICE/attribution/пометка модификаций/ShareAlike или другие применимые условия |
| Решение | Проверяющий, дата, допущенные операции, нерешённые вопросы и статус approved/blocked |

Сжатие, хеширование и обучение не считаются способом автоматически устранить условия источника. Нельзя ни объявлять любые weights свободными от условий корпуса, ни автоматически переносить лицензию корпуса на весь наш код без разбора применимости. Для спорного случая требуется отдельное решение до выпуска.

Синтетические данные LLM не считаются автоматически свободными от ограничений и не заменяют независимую тестовую выборку. Личный ввод, логи и содержимое чужих приватных репозиториев запрещены как источники. Известные права на данные не означают, что персональные сведения внутри них безопасно распространять.

## Текущее состояние

Для первого локального эксперимента допущены конкретные ru_RU.dic и en_US.dic LibreOffice с сохранением полных первичных уведомлений; commit, SHA-256 и ограничения находятся в data/sources.json и data/README.md. Исходные словари и производные таблицы находятся только в игнорируемом build/. Их выпуск в составе приложения не одобрен. Частотный test-корпус обычного пользовательского ввода и production weights не выбраны. Проверка применимости условий нового источника по-прежнему обязательна; исследовательская записка сама по себе не даёт разрешения на произвольные данные.

Для опыта 002 отдельно допущены официальные Tatoeba CC0-only sentence exports только для локальной оценки, без обучения и калибровки. Паспорт: data/evaluation-002-sources.json; первичные условия и ограничения: data/notices/Tatoeba-CC0-REVIEW.md. Это языковые примеры с возможным шумом и смещением, не естественная частотная выборка обычного ввода. Такой допуск не меняет запрет автоматического обучения на пользовательском вводе, не одобряет выпуск весов/корпуса и не заменяет отдельную проверку новых источников.

Справочные первичные источники: [Creative Commons: данные и лицензии](https://creativecommons.org/faq/), [CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/).

Для опыта 003 отдельно проверены .aff EN/RU и Hunspell 1.7.5: data/morphology-003-sources.json и data/notices/MORPHOLOGY-003-REVIEW.md. Разрешён только локальный контроль spell и PFX/SFX-ablation с сохранением остальных байтов, notices и пометки модификаций. Новые данные/библиотека не добавлены в пакет. Новый отложенный блок того же Tatoeba snapshot используется только для оценки; это не новый жанр и не разрешение на пользовательскую историю.

Для опыта004 отдельно допущены pinned EN/RU Markdown главы Rust Book только для local evaluation: data/evaluation-004-sources.json и data/notices/TECHNICAL-004-REVIEW.md. Сохранены полные первичные notices; candidate path metadata опубликованы отдельно для replay, исходные тексты и case/action TSV только в build/. Нет обучения или разрешения на выпуск данных/моделей. Oracle code-protection не является подтверждением безопасного системного контекста.

Опыт005 использует производные прежних словарей и собственные синтетические prefix/intent сценарии по data/evaluation-005-sources.json. Context labels отделены от policy inputs, collision contradictions заданы намеренно. Natural error rates и независимая семантическая разметка не заявляются. Features/labels/actions не публикуются и не становятся пользовательской историей. Новый естественный корпус дляSYS-238 потребует отдельного допуска.

Опыт006 использует новые главы прежних pinned EN/RU Rust Book источников с отдельным расширением локального допуска до ranks20..39 (data/evaluation-006-sources.json). Natural prefixes и исходный Keep-intent отделены от synthetic corruption и unknown no-action stress. Label files не открываются policy CLI. Никаких данных пользователя или новых обученных weights; release_approved=false. Принятый ADR не заменяет отдельный допуск данных для упаковки/выпуска.
