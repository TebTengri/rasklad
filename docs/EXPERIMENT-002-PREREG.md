# Предварительный протокол опыта 002

SYS-233, 2026-11-11. Точные параметры находятся в [JSON протокола](../data/experiment-002-protocol.json), замороженном коммитом d682b1e до получения текстов. SHA-256: 4e38458069c2aa0eb884392dc8eda841d2ecf1f27bcb7e2174c87d1e6c1889b8. Порогов после нового test не подбираем, исключений под найденные ошибки не добавляем. Claude реализует C++ стенд без чтения нового корпуса; Codex готовит данные, проверяет реализацию и запускает измерение.

## Что проверяем

| Гипотеза | Наблюдение в пользу | Наблюдение против / предел вывода |
| --- | --- | --- |
| H1: модель покрывает пробелы exact | Восстанавливает новые wrong-layout токены, отсутствующие в обоих полных словарях | Нет дополнительных восстановлений; любые найденные восстановления всё равно оцениваются вместе с ложными изменениями |
| H2: словарь → модель даёт безопасную прибавку | Есть восстановления сверх exactFull и нет добавленных unsafe changes на новых случаях | Любое добавленное небезопасное изменение опровергает строгую формулировку для этой выборки; также считаем предотвращённые изменения и разность |
| H3: подтверждение словарём уменьшает риск | Пересечение решений twoScore и exactFull уменьшает false changes относительно exactFull | Риск не снижается; выигрыш оценивается вместе с потерей полезных замен, а не одним precision |
| H4: абсолютные оценки полезнее разности | TwoScore уменьшает unsafe changes относительно Single-D при ненулевом покрытии | На выбранных случаях преимуществ нет; результат не обобщать на любую возможную калибровку |

Это проверка конкретных вариантов, не доказательство полезности/бесполезности всех маленьких моделей. Нейросеть и персонализация не входят в этот опыт. Вывод для каждой гипотезы: поддержана на выборке / опровергнута на выборке / недостаточно данных. Автоматический системный ввод по результатам не включается.

## Справедливость сравнения

Остаются исходные n-gram weights/algorithm/split опыта 001; они заново воспроизводятся только из прежнего train. Пороги фиксированы: D gap 2,5; twoScore minAlternative=-13, maxObserved=-9, gap=2,5. Новая выборка не используется для обучения, калибровки или выбора порогов. ExactTrain содержит те же обучающие типы, exactFull — все ранее допущенные словарные записи. Разница бюджетов обучающих данных обозначается явно; новый корпус не является частью ни одного словаря-источника, но буквальные совпадения слов ожидаемы.

Каскад exactFullThenTwoScore сначала сохраняет слово при observed exact hit, иначе исправляет при alternative hit, иначе обращается к twoScore. TwoScoreConfirmedByExactFull сохраняет observed hit, иначе исправляет только при согласии twoScore и alternative exact hit; другие случаи пропускает.

Сжатый exact-кандидат — точный front-coded индекс с поиском, не вероятностный фильтр. Его результаты не доказывают невозможность более эффективного FST/DAFSA. Affix flags не разворачиваются и морфологический словарный lookup не реализован: выигрыш модели на словоформах нельзя выдавать за превосходство над всеми словарными методами. По итогам следует отдельно решить, нужен ли такой baseline.

## Данные и чтение результата

[Паспорт Tatoeba CC0](../data/evaluation-002-sources.json), [проверка первичных условий](../data/notices/Tatoeba-CC0-REVIEW.md). В Git не входят предложения/IDs/словарные файлы/weights. В upstream четыре TSV колонки; техническая timestamp-колонка удаляется до входа стенда. Подготовка воспроизводится offline скриптом tools/prepare_cc0_evaluation.py из отдельно скачанных по паспортным URL compressed файлов. Проверять compressed, upstream и prepared SHA-256; версия источника — snapshot 2026-11-07, автоматической синхронизации нет.

Для каждого языка выбираем 5000 предложений по SHA-256(seed + NUL + decimalID), после точного dedup текста с сохранением меньшего numericID. Отбор до токенизации; seed не меняется. Корпус — добровольные оригинальные языковые примеры с возможным шумом, не обычный ввод и не гарантия корректности языка каждого токена. Неравномерность авторов и повторяющиеся конструкции ограничивают статистическую независимость.

Токены получаются из известного текста до wrong-layout конверсии, с фиксированным обрезанием внешней пунктуации; внутреннюю сохраняем. Это oracle boundaries, не проверка сегментации живой клавиатуры. Wrong копии только для native letter-only токенов длины 1..32, короткие 1..3 всегда Abstain. Все исходные непустые токены имеют intent Keep, включая неподдерживаемые.

Неоднозначные ключи из обоих полных словарей — отдельные safety negatives. В дополнение: фиксированные искусственные code/URL/name fixtures, все cross-lexicon пары длиной >=4 и 256 детерминированных шумовых токенов для каждой раскладки вне словарей. Шум размечен по искусственному intent Keep; отсутствие в словаре не доказывает, что строка не является словом какого-либо языка.

Считаем occurrences и unique types, направления, длины, known/OOV, добавленные и предотвращённые unsafe changes на одних случаях. Повторы не выдаём за независимые испытания. Expected precision при 0,1% / 1% / 5% ошибочной раскладки — аналитические сценарии по условным частотам выборки, не измеренная точность эксплуатации.

## Ресурсы

Размер serialized tables/index, warm latency с явно указанными повторениями и sample size. Fresh-process probe загружает только один model/index artifact и фиксированные синтетические ключи; train/corpus списки не удерживает. Память измерять у фактического процесса predictor, а не supervisor bubblewrap. Cold означает новый процесс с неизвестным/тёплым файловым кешем, а не гарантированно холодный OS cache. Формат weights/индекса и все dataset-derived artifacts остаются в build/, release_approved=false.
