# SYS-225: ручное исправление двойным Shift (проект, срез 1)

Дата: 2026-11-21. Статус: проект + офлайн-реализация; живого запуска нет.

## Что делает срез 1

Только текущее слово в preedit (ещё не отданное приложению):

- Набрано `ghbdtn` (видно как preedit), двойной Shift → preedit показывает
  `привет`. Space отдаёт показанное одним commit.
- Повторный двойной Shift до Space → снова `ghbdtn` (отмена).
- В этом варианте автоисправления нет: Space без жеста отдаёт исходное слово.

Не входит в срез 1 (отдельные решения):

- Уже отданное слово и фраза (тройной Shift). Нужен deleteSurroundingText или
  BackSpace по тексту, уже принятому приложением: новая граница безопасности
  (сейчас запрещено в fcitxlab.cpp), требует отдельного согласования владельца.
- Клавиши `[ ] ; ' , .` и backtick (х ъ ж э б ю ё): сейчас прерывают слово;
  слова с этими буквами срез 1 не исправляет.
- Обратное направление ru → en (движок должен быть keyboard-us).

## Распознавание жеста

- Касание = нажатие и отпускание Shift_L или Shift_R без других модификаторов
  и без другой клавиши между ними.
- Двойной жест = два касания, второе нажатие не позже 400 мс после первого
  отпускания (время из KeyEvent::time(), без своих часов).
- Нажатие Shift при непустом буфере больше не сбрасывает слово: решение
  откладывается. Shift + буква (заглавная) → как раньше: исходное слово
  отдаётся, далее bypass до границы.
- Любая другая клавиша между касаниями, смена поля/окна, сброс, потеря фокуса,
  смена возможностей обнуляют счётчик касаний (буфер, как раньше, без commit).
- Shift-касания при пустом буфере проходят в приложение без изменений.
- Нажатия и отпускания Shift никогда не поглощаются: приложение видит
  симметричные press/release модификатора.

## Конфликт с настройками Fcitx

По умолчанию Fcitx 5 использует Shift_L как AltTriggerKeys (временное
переключение метода). В стенде профиль изолирован. В продукте это нужно
проверить на версии пользователя и документировать; молча менять
пользовательский конфиг Fcitx нельзя.

## Проверка (офлайн, закрытый Sway + Chromium)

1. `ghbdtn` + двойной Shift + Space → `привет `.
2. `ghbdtn` + двойной Shift ×2 + Space → `ghbdtn `.
3. `ghbdtn` + Shift+`a` → `ghbdtn` + `A`, без преобразования.
4. `ghbdtn` + два медленных касания (> 400 мс) + Space → `ghbdtn `.
5. Пустое поле + двойной Shift → ничего не вставлено.

## Результат офлайн-проверки (2026-11-21)

`python3 -I tools/wayland_ime_lab.py --run --manual-suite`: 14/14, данные в
data/manual-gesture-001-result.json. Сборка: `tools/fcitx_manual_lab.pro` в
build/chromium-ime/manual-addon; логика: `tests/manual_gesture/manual_gesture.pro`.

Найдено и исправлено по ходу:
- одиночный Shift при пустом буфере включал bypass, и следующее слово шло без
  preedit (поймано проверкой «Shift перед словом»);
- Grok (FIX-FIRST): Enter/Tab/пунктуация отдавали исходное ASCII вместо
  показанного; теперь любой путь, завершающий слово, отдаёт показанное
  (проверено Escape, тот же путь); брошенное отпускание Shift сбрасывает жест.

Помощник виртуальной клавиатуры не получил Enter: тот же двоичный помощник
используется в живом стенде. Команды shift2/shiftslow/shifta доступны только
при RASKLAD_MANUAL_LAB=1 и запрещены в slack_injector.

Остаётся: живой Slack для жеста не запускался; AltTriggerKeys на системе
пользователя не проверен; срезы «отданное слово / фраза» требуют решения.
